| 2026-11-09 | **LLM-utilised placement**: the engine enumerates hard-valid slots, scores them (soft penalties from built-in placement wisdom + stored constraint rules), and places at `argmin(penalty, start)`; with `smart_placement=off` this degenerates to the legacy earliest-free-slot behaviour | user asked for the LLM to "choose time slots" (avoid work right after tiring lectures, avoid math right after math class) — feasible only if semantic preference becomes data the planner can weigh | confirmed |

| 2026-11-09 | New tables `event_annotations` (external event → `subject`, `fatigue` 0–3, `source` heuristic\|llm\|user) and `constraints` (`kind`, `params` JSON, `enabled`, `hard`, `source`, `label`); `jobs` gains `placement_source` (`engine`\|`llm`) and `placement_note` | annotations give the planner semantics (a 3h draining lecture ≠ an empty morning); constraints make NL preferences enforceable data; receipts make placement explainable and debuggable | confirmed |
| 2026-11-09 | External events are annotated at import-time (one batched LLM call for missing events; heuristic fallback per event: ≥3h→f3, ≥2h→f2, ≥45m→f1, +1 `lab`; keyword/regex subject map; all-day events are fatigue 0); `POST /api/events/annotate` (re)annotates on demand; engine only reads the table | purity + offline-first: annotation is never produced inside the engine; LLM failures degrade annotation quality, never import/replan correctness | confirmed |
| 2026-11-09 | Constraints are compiled from natural language two ways: LLM chat tool `add_constraint` (structured, bounds-validated) and a deterministic offline NL parser (`constraints.parse_nl`) for common utterances; kinds: `post_fatigue_buffer`, `subject_gap`, `interleave` (soft-only), `blocked_day_part` | "avoid math right after math class" must work with zero configuration, with an LLM, and via the REST API — same underlying validator for all three | confirmed |
| 2026-11-09 | Hard constraints relax to soft penalties when no candidate survives them; the job is placed anyway and `placement_note` records the relaxation | dropping pending/revision work silently is strictly worse than a feasible-but-suboptimal plan; deadlock must be impossible | confirmed |
